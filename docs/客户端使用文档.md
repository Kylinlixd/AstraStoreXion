# AstraStoreXion 客户端使用教程

当前稳定客户端是 Python SDK 1.2，它用于 Django 等受信任的服务端程序。浏览器不得直接连接 Xion，也不得持有服务密钥；博客管理端始终调用 Django API。

## 服务器 Bash 命令：xionctl

如果需要在服务器上查看或操作文件，不要直接进入 `/var/lib/astrastore-xion/objects` 删除对象；对象必须和 JSON manifest 一起维护。构建并安装命令行工具：

```bash
make xionctl
sudo XIONCTL_BINARY="$PWD/bin/xionctl" ./deploy/xionctl-install.sh
```

它默认读取权限为 `0600` 的 `/etc/astrastore-xion.env`，常用操作如下：

```bash
xionctl health
xionctl capacity
xionctl config
xionctl config --max-upload-size 100M
xionctl list
xionctl list --limit 20 --offset 0
xionctl info <file-id>
xionctl upload ./example.png
xionctl download <file-id> /tmp/example.png
xionctl delete <file-id> --yes
xionctl logs
xionctl logs --lines 100
xionctl logs --since 1h
xionctl logs --follow
```

`list`、`info`、`upload` 输出 JSON，便于继续交给 `jq`；`capacity` 使用类似 Linux `df -h` 的人类可读表格，不输出 JSON；`download` 先写同目录临时文件，完成后再替换目标文件；`delete` 没有 `--yes` 会拒绝发送请求。也可以用 `--api`、`--token`、`--env-file` 和 `--timeout` 临时覆盖配置，但服务令牌不要写进脚本、日志或截图。

`logs` 固定查看 `astrastore-xion.service` 的 systemd 日志，相当于安全封装了 `journalctl -u astrastore-xion.service`。它不接受任意 service 名称，也不会重启服务或修改数据；如果提示权限不足，请使用有 journal 读取权限的账号或 `sudo xionctl logs`。

`capacity` 返回类似 `df -h` 的表格，直接对齐显示 `Size`（总容量）、`Used`（已用）、`Avail`（可用）、`Use%`（使用率）和上传状态，并附带保护阈值与文件对象数量。生产默认在使用率达到 90% 时暂停新上传；状态会显示为 `已暂停上传，释放空间后自动恢复`。读取、下载和删除不受影响，空间释放后上传自动恢复。

`config` 查看 Xion 最大上传大小；例如 `xionctl config --max-upload-size 1G` 会备份 `/etc/astrastore-xion.env`、更新 `XION_MAX_UPLOAD_BYTES` 并重启服务。支持 `K`、`M`、`G` 后缀，不能设置为 0 或负数。博客后端还存在独立的上传校验，博客当前默认上限同样为 1 GiB。

## 五分钟本地体验

先启动单节点服务：

```bash
export XION_SERVICE_TOKEN="$(openssl rand -hex 32)"
export XION_LISTEN_ADDR=127.0.0.1:8081
export XION_DATA_DIR="$(mktemp -d)"
go run ./core/apigateway
```

另开一个终端检查服务。不要把真实密钥写入 shell 历史、截图或仓库：

```bash
curl --fail http://127.0.0.1:8081/healthz
curl --fail http://127.0.0.1:8081/readyz
```

推荐直接运行字节校验脚本：

```bash
XION_BASE_URL=http://127.0.0.1:8081 \
XION_SERVICE_TOKEN="$XION_SERVICE_TOKEN" \
./scripts/smoke-test.sh test/fixtures/generated/upload-smoke.txt
```

脚本会完成上传、状态查询、下载、SHA-256 比对与删除，临时目录只在本次运行内创建和清理。

## Python 完整示例

```python
import os

from astrastore_xion import XionClient, XionConfig, XionHTTPError


config = XionConfig(
    api_gateway="http://127.0.0.1:8081",
    service_token=os.environ["XION_SERVICE_TOKEN"],
    connect_timeout=3,
    read_timeout=30,
    max_retries=2,
)

try:
    with XionClient(config) as client:
        assert client.health() == "ok"

        with open("example.pdf", "rb") as source:
            stored = client.upload_file(
                source,
                "example.pdf",
                {"source": "tutorial"},
            )

        print(stored.file_id, stored.checksum, stored.size)

        with open("downloaded-example.pdf", "wb") as target:
            client.download_file(stored.file_id, target)

        status = client.get_file_status(stored.file_id)
        assert status.checksum == stored.checksum

        page = client.list_files(limit=20, offset=0)
        print(page.count)

        client.delete_file(stored.file_id)
except XionHTTPError as error:
    print(error.status_code, error.code, error.message)
```

上传请求不会自动重试，避免网络边界不确定时生成重复对象。GET 和 DELETE 仅在连接失败或 502、503、504 时执行有界重试。

### SDK 1.2：大文件续传与下载校验

`upload_file` 适合小文件的一次性提交。大文件改用分片会话，服务端按 `received_bytes` 支持断点续传，并在每一片和整体各校验一次 SHA-256：

```python
from astrastore_xion import XionChecksumError

with XionClient(config) as client:
    with open("large.zip", "rb") as source:
        stored = client.upload_large_file(
            source,
            "large.zip",
            metadata={"owner": "blog"},
            chunk_size=8 * 1024 * 1024,
            progress=lambda done, total: print(f"{done}/{total}"),
        )
```

`upload_large_file` 需要可 seek 的流或 `bytes`，因为会话必须先声明总大小。任一环节失败时会自动中止会话，释放它占用的 owner 配额；也可以手动控制会话：

```python
session = client.start_upload_session("large.zip", size=104857600)
print(session.upload_id, session.received_bytes)
client.abort_upload_session(session.upload_id, ignore_errors=True)
```

下载时可选启用校验和验证。服务端在 `ETag` 中返回 `sha256-<hex>`，SDK 边写边算，不一致就抛 `XionChecksumError`，避免把静默损坏的数据写入磁盘：

```python
with open("downloaded.zip", "wb") as target:
    client.download_file(stored.file_id, target, verify_checksum=True)
```

## 配置文件

```yaml
api_gateway: http://127.0.0.1:8081
service_token: ${DO_NOT_COMMIT_REAL_TOKEN}
connect_timeout: 3
read_timeout: 30
max_retries: 2
retry_interval_seconds: 0.25
chunk_size: 1048576
```

生产环境建议从进程环境或受限的 secret 文件注入 `service_token`，不要提交包含真实值的 YAML。

## 直接 HTTP API

所有文件接口都要求 `Authorization: Bearer ...`。健康与就绪检查公开，但服务本身应只监听回环地址。

```bash
curl --fail-with-body \
  -H "Authorization: Bearer $XION_SERVICE_TOKEN" \
  -F "file=@example.pdf;type=application/pdf" \
  -F 'metadata={"source":"curl-tutorial"}' \
  http://127.0.0.1:8081/api/v1/files
```

接口列表：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/healthz`、`/health` | 进程健康 |
| `GET` | `/readyz`、`/ready` | 数据目录可写 |
| `POST` | `/api/v1/files` | multipart 上传，字段名为 `file` |
| `GET` | `/api/v1/files?limit=100&offset=0` | 稳定分页列表 |
| `GET` | `/api/v1/files/{id}/status` | 元数据和 SHA-256 |
| `GET` | `/api/v1/files/{id}` | 流式下载 |
| `DELETE` | `/api/v1/files/{id}` | 幂等删除 |
| `GET` | `/api/v1/files/capacity` | 容量与自动暂停状态（需服务令牌） |

错误格式固定为：

```json
{
  "error": {
    "code": "not_found",
    "message": "file does not exist"
  }
}
```

## 在博客中使用

博客采用双存储策略：

1. 新上传文件在功能开关启用后写入 Xion。
2. 历史 `/media/` 文件继续由原目录和 Nginx 提供。
3. Django 保存文件名、类型、大小、校验和和存储后端，并生成稳定下载地址。
4. Vue 管理端只展示进度、类型和稳定链接，不感知服务密钥或内部文件 ID。

管理端文件中心内置“使用教程”，包含上传、复制链接、插入文章、下载/删除和常见问题五步流程。

## 常见问题

- `401 unauthorized`：服务密钥缺失或不一致。
- `413 file_too_large`：文件超过 `XION_MAX_UPLOAD_BYTES`，博客默认上限为 1 GiB。
- `507 storage_paused`：存储达到自动保护阈值，先删除不需要的文件释放空间；服务会自动恢复上传。
- `503 not_ready`：检查数据目录是否存在、可写，以及磁盘是否已满。
- 可下载但不能预览：通常是浏览器不支持该 MIME，不代表文件损坏。
- 上传结果不确定：不要盲目重试 POST；先在业务数据库或 Xion 列表中确认是否已生成对象。

Go、Java、Node.js 目录仍保留用于后续兼容性工作，本轮生产融合只承诺 Go 服务端 HTTP API 与 Python SDK 1.2。
