# Xion 文件回收站与恢复设计

## 目标

将现有文件删除从立即物理删除升级为可恢复的软删除，避免博客误删封面、附件后无法找回。活动文件的列表、下载和状态接口保持原有行为；回收站通过独立接口访问。

## 存储布局

```text
<data>/trash/<file-id>/object
<data>/trash/<file-id>/manifest.json
```

删除时把活动对象和清单移动到同一个回收站目录。清单保留原文件字段并增加 `deleted_at`，文件状态仍为 `available`，但只在回收站接口中返回。恢复时把对象和清单移动回活动目录。文件 ID 不变，原下载链接恢复后继续有效。

## API

```text
GET  /api/v1/trash?limit=100&offset=0
POST /api/v1/files/{file-id}/restore
```

活动文件的 `DELETE /api/v1/files/{file-id}` 变为幂等软删除。恢复目标已经存在或回收站清单损坏时返回冲突/服务错误，不覆盖活动文件。暂不提供公开永久删除接口，物理清理留给后续保留策略和管理员任务。

## 一致性与恢复

- 移动操作在同一数据文件系统内使用 `rename`，每一步后同步目录。
- 就绪检查同时校验活动目录和回收站目录，发现缺失对象、孤儿对象、临时清单或非法 ID 时拒绝 ready。
- 回收站文件不会计入活动对象列表；容量统计仍计入磁盘实际占用，并新增回收站计数/字节字段。
- 服务重启后回收站内容可查询和恢复。

## 测试

- 存储层覆盖软删除、重复删除、回收站列表、恢复、重启恢复和活动 ID 冲突。
- HTTP 层覆盖鉴权、回收站分页、恢复响应和原有删除/下载回归。
- `go test ./...`、`go vet ./...` 和 race 测试必须通过。
