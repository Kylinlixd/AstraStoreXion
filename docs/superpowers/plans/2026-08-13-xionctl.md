# xionctl Server CLI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and document a safe `xionctl` binary for inspecting and mutating Xion files from the server shell.

**Architecture:** Keep the CLI in `cmd/xionctl` with small internal config/client helpers and a command dispatcher. Use the existing Xion HTTP API rather than touching its disk layout directly; install the resulting binary to `/usr/local/bin/xionctl`.

**Tech Stack:** Go 1.23+, standard library `flag`, `net/http`, `mime/multipart`, `net/url`, `encoding/json`, `httptest`.

### Task 2: Implement config and HTTP client

**Files:**
- Create: `cmd/xionctl/main.go`
- Create: `cmd/xionctl/config.go`
- Create: `cmd/xionctl/client.go`

- [ ] **Step 1: Implement env-file parsing and precedence.**

Parse comments, blank lines, `KEY=value`, and optional single/double quotes. Resolve `XION_API_URL` first, otherwise normalize `XION_LISTEN_ADDR` to `http://<addr>`; default to `http://127.0.0.1:8081`. Resolve `XION_SERVICE_TOKEN`, timeout, and env-file path without printing secrets.

- [ ] **Step 2: Implement authenticated JSON, multipart upload, streaming download, and structured error parsing.**

Use `Authorization: Bearer <token>`, request timeouts, URL path escaping, status handling, and a `downloadAtomic` helper that closes and removes the temporary file on any error before renaming it.

- [ ] **Step 3: Implement command dispatch and safe defaults.**

Provide `health`, `list`, `info`, `upload`, `download`, and `delete`; write JSON for file operations, concise readiness output, usage errors to stderr, and require `--yes` for delete.

- [ ] **Step 4: Run focused tests and make them pass.**

Run: `go test ./cmd/xionctl -count=1`

Expected: all CLI tests pass.
